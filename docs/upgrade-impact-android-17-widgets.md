# EE-31 — Change impact assessment: home-screen widgets module → Android 17 (API 37)

**Status: DRAFT for human review.** Committed before any production code change on branch
`devin/ee-31-widgets-android-17`. Baseline: `main` @ `8fde0b91` (v1.16.5, compileSdk/targetSdk 35).
Scope: `com.futsch1.medtimer.widgets` (`WidgetImpl.kt`, `WidgetLineProvider.kt`,
`NextRemindersWidgetProvider.kt`, `LatestRemindersWidgetProvider.kt`, `WidgetUpdateReceiver.kt`,
`WidgetIds`), widget layouts `res/layout/*widget*`, `res/xml/*_widget_info.xml`, and the toolchain
needed to compile the whole app with compileSdk/targetSdk 37.

Sources: developer.android.com "Behavior changes" pages for Android 16 (all apps / targeting 36) and
Android 17 (all apps / targeting 37), and the AGP release notes; all read on 2026-10-12. Each row quotes
the file:line evidence that was used to decide applicability.

Legend — **Applies**: `Y` = code change required; `RC` = runtime-check (no code defect found, but the
behaviour must be verified at runtime / guarded by a test); `N` = not affected (evidence given).

## 3. Explicitly not affected (summary with evidence)

- IMP-03, IMP-04, IMP-05, IMP-06, IMP-08 … IMP-14 above: no `screenOrientation`/aspect-ratio attributes, no ordered broadcasts, no reflection on framework internals, no `INTERNET`, no bitmaps in RemoteViews, explicit immutable `PendingIntent`, predictive back already enabled.
- Android 16 "16 KB page size": app has no native libraries (`app/src/main/jniLibs` absent; `./gradlew assembleDebug` output has no `lib/`), so not affected.
- Android 16 "Intent redirection hardening" / Android 17 "Restrict implicit URI grants": the widget sends no intents with nested intents or URI grants.
- Android 17 `usesCleartextTraffic` deprecation: manifest already sets `android:usesCleartextTraffic="false"` (`AndroidManifest.xml:33`).
- Android 16/17 Bluetooth, Health, media, IME, touchpad, keystore, OTP, cross-profile changes: no related API usage in the module (`grep` for `Bluetooth|MediaStore|InputMethod|KeyStore` in `widgets/` → none).

## 4. Known verification limits on this VM

- The API 36/37 emulator images crash-loop SurfaceFlinger under the headless emulator (gfxstream `hasReadColorBufferDma` assertion), so **API 37 UI behaviour (IMP-01 at runtime) cannot be screenshotted here**; it is covered by the Robolectric SDK 37 guard test, by `adb install` on `api37`, and by the API 37 CI run of `connectedDebugAndroidTest` (result to be reported from the real run).
- API 35 is used for screenshots/recordings and `connectedDebugAndroidTest`.

## 5. Rollback plan

- All changes live on branch `devin/ee-31-widgets-android-17`; `main` is untouched. Rolling back = not merging, or `git revert` of the PR merge commit.
- Toolchain and SDK bumps are four separate commits (wrapper+AGP/Kotlin → dependencies → compileSdk 37 → targetSdk 37), each verified with `./gradlew assembleDebug`, so a partial rollback (e.g. keep compileSdk 37 but return to targetSdk 35 if IMP-01 ever bites in production) is a single-commit revert of the `targetSdk` commit — the widget code itself has no API-37-only calls.
- Module changes are one commit per IMP id (`IMP-07: …`), individually revertible; tests and docs are separate commits.
- Room schema is not migrated by this ticket (no `@Database` version change), so no data rollback is involved.
